# D-CRASH-11

same algorithm on bytes (ASCII whitespace), hooks run

* **Class:** CRASH (COMPATIBILITY §5.1)
* **Owner:** WP-18; the first package of the register row owns this file and
  `tests/differential/divergences/D-CRASH-11.yaml` (WBS "Divergence files", ADR-071).
* **Status:** implemented by WP-18 (`snp_git::Git::pre_push`, `crates/snp-git/src/git.rs`; ADR-022, ADR-052).

## Register entry (COMPATIBILITY §5.1)

| pre-commit 4.7.0 | snp |
|---|---|
| non-UTF-8 pre-push stdin → `UnicodeDecodeError` exit 3, push blocked (X13-HI-04) | same algorithm on bytes (ASCII whitespace), hooks run |

## Rationale

git ref names are bytes: a branch created under a Latin-1 locale (`refs/heads/caf\xe9`) is legal, and git passes it
unchanged on the pre-push stdin. `hook_impl._pre_push_ns` decodes the whole stdin strictly (`stdin.decode()`,
`hook_impl.py:128`) before looking at any line, so every push that involves such a ref crashes with
`UnicodeDecodeError` (exit 3) and the push is blocked — the user cannot push at all with the hooks installed.

snp keeps pre-commit's algorithm byte for byte for valid UTF-8 (Python `str.splitlines()` + `str.rsplit(maxsplit=3)`,
X13-HI-03's fail-closed `ValueError` included; the V-PP vectors prove equality). Only when the stdin is not valid
UTF-8 does it run the same algorithm on bytes — `bytes.splitlines()` (`\n`, `\r`, `\r\n`) and `bytes.rsplit(maxsplit=3)`
(ASCII whitespace), exactly what Python would do on the undecoded bytes — and the hooks then check the push normally;
`PRE_COMMIT_LOCAL_BRANCH`/`PRE_COMMIT_REMOTE_BRANCH` carry the raw bytes (Unix). Malformed lines still fail closed
with the same `ValueError`. No push that pre-commit lets through is checked differently, so the change cannot fail
open (K5): it turns a crash into a checked push.

## Examples

A repository whose `master` (`d1fe…`, any sha) is pushed to a new remote branch named `caf\xe9`: git writes the stdin
`refs/heads/caf\xe9 <sha> refs/heads/caf\xe9 0000000000000000000000000000000000000000\n`, the hook runs
`pre-commit hook-impl --hook-type=pre-push --hook-dir .git/hooks -- origin ../remote.git`.

pre-commit 4.7.0 (oracle `pc470-py312`), exit **3**, stdout:

```
An unexpected error has occurred: UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe9 in position 14: invalid continuation byte
Check the log at <store>/pre-commit.log
```

snp: the line splits into `refs/heads/caf\xe9`, `<sha>`, `refs/heads/caf\xe9`, the null sha; the remote has no history,
so `git rev-list <sha> --topo-order --reverse --not --remotes=origin` lists the new commits, the first is a root and
the namespace is `--all-files` — the configured `pre-push` hooks run on all files (`echo` prints them), exit **0**.

Regression tests: `crates/snp-git/tests/catalog.rs` `x13_hi_04_non_utf8_pre_push_stdin_runs_on_bytes`, the V-PP
vectors with invalid UTF-8 (`crates/snp-git/tests/vectors/v_pp.json`, generated by `gen_v_pp.py` with the oracle:
`pre_commit` holds pre-commit's `UnicodeDecodeError`, `snp` the bytes records) and the fuzz target `git_pre_push`.
