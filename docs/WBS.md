# snp — Work breakdown structure

Waves: **W0** one skeleton package; **W1** eight leaf packages in parallel; **W2** seven dependent packages in
parallel; **W3** integration, binary, differential tests, performance gates, release and documentation (seven
packages). Every package description below is self-contained; `NN §x` = `docs/research/NN-*.md` section x; `ARCH §x`
= `docs/ARCHITECTURE.md`; `ADR-n` = `docs/DECISIONS.md`; `D-…` = `docs/COMPATIBILITY.md` §5; catalog IDs `T10-…`,
`X13-…`, `M11-…` = ARCH §13.8. This revision applies design review round 2 (ADR-056…ADR-080, DECISIONS Appendix B).

## Rules (all packages)

* **Contracts first.** After WP-00 every public signature of ARCH §1.4 exists as a compiling stub and is referenced by
  the crate's `tests/api.rs`. A package may *compile* against any crate but may rely on the *behaviour* only of packages
  of earlier waves — plus the W0 working baselines (ARCH §1.2 W0 row: spawn, executable resolution, xargs partitioning,
  file locks, durable writes, the pycompat composites) and the single documented intra-wave milestone below. Changing a
  signature needs an ADR (DECISIONS.md, superseding entry) approved by the integration lead (WP-00 owner role) and the
  owners of every consuming package.
* **Intra-wave milestone (ADR-071).** WP-26 merges its milestone **M1** first in W2: the frozen `snp_hooks::framework`
  implementation and the Appendix A help goldens of every pre-commit-hooks console script. WP-27 depends on `WP-26 (M1)`;
  its acceptance items marked **[M1]** run once M1 has merged. No other same-wave dependency exists.
* **Disjoint ownership.** Within a wave no two packages own the same path. WP-00 pre-creates every shared file
  (`[workspace.dependencies]`, `crates/snp/tests/it/main.rs` with one empty module file per owner, `fuzz/Cargo.toml`
  with stub target files, `snp-lang/src/langs/<lang>.rs` and every external dependency the language backends need in
  `crates/snp-lang/Cargo.toml`, `snp-hooks/src/pch/<group>/mod.rs`, `snp-hooks/src/framework/`,
  `snp-hooks-data/src/generated/parity_gates.rs`, `xtask/src/tasks/<task>.rs` stubs, the per-ID divergence stubs, the
  catalog index) so owners only fill files they own. Nobody edits the root `Cargo.toml` after W0 (new external
  dependency ⇒ ADR + integration lead). `Cargo.lock` is regenerated (`cargo update -w`), never hand-merged.
  `deps.lock` changes only through a dedicated PR that runs every gate (ADR-061).
* **Integration-lead files (ADR-081).** After W0 these WP-00 files stay with the integration lead even where a
  package glob would cover them; they change only through the integration lead (on a package's request, a
  signature-change ADR or a `deps.lock` bump): `crates/snp-core/**`; the contract tests that span several packages,
  `crates/snp-lang/tests/api.rs` (WP-16/24/25) and `crates/snp-hooks/tests/api.rs` (WP-26/27); the ADR-061 drift checks
  `crates/snp-config/tests/user_crates.rs` and `crates/snp-files/tests/user_crates.rs`; `crates/snp/tests/it/main.rs`;
  `fuzz/Cargo.toml`, `fuzz/Cargo.lock`; `xtask/Cargo.toml`, `xtask/src/main.rs`, `xtask/src/workspace.rs`,
  `xtask/src/tasks/mod.rs` and WP-00's own tasks (`check_dag`, `check_unsafe`, `lint_guards`, `catalog_index`, `oracle`,
  `xtask/oracle/requirements-pc462.*`); `.github/scripts/**`; `tests/catalog/**`. Shared manifests: `fuzz/Cargo.toml`
  depends on every crate a §13.5 target needs, `snp-core` and `snp-os` included; `xtask/Cargo.toml` pre-declares clap,
  clap_complete and clap_mangen for WP-12's `completions`; a fuzz-target or xtask-task owner needing a further workspace
  dependency there asks the integration lead. `crates/snp-hooks/Cargo.toml` belongs to WP-26, which adds a dependency
  that WP-27 requests (WP-00 pre-declares `memchr` and `bstr`, anchored in `pch/{p1,p2,caveats}/mod.rs`).
* **Stub hygiene.** Every stub module file has one owner and starts with its own
  `#![expect(clippy::todo, reason = "W0 stub, removed by WP-xx")]` (never crate-level in a shared `lib.rs`); when the
  owner removes the file's last `todo!()` the unfulfilled expectation fails CI until the owner deletes the attribute.
  `impl Iterator` stubs use `core::iter::from_fn(|| todo!())`.
* **Definition of done (every package):** both clippy invocations of ARCH §1.3 clean under `-D warnings`
  (`--lib --bins` with the full deny set incl. `arithmetic_side_effects`, `disallowed_macros` and the panicking-API
  `disallowed_methods`; test targets with `assert*!`/arithmetic relaxed), `unsafe_code = "forbid"`, MSRV 1.98 check,
  rustdoc on every public item naming the Python/pre-commit source it reproduces, `Debug` on every public type, every
  parser has a fuzz target (60 s smoke in CI, 300 s nightly; 256 KiB stacks, 512 MB RSS), acceptance tests green on
  Linux, macOS and Windows unless marked `posix`, messages golden-tested in both brands, every catalog row the package
  owns (table below) ported as a test named with its namespaced ID, the stub files of every divergence ID it owns filled
  (`docs/divergences/<ID>.md` rationale and examples; `tests/differential/divergences/<ID>.yaml` scenario, executed by
  WP-35's harness from W3 on), and every timing threshold of its acceptance list present as a release-mode
  `#[ignore = "perf"]` test with a 3× margin (run by the `perf-smoke` CI job; WP-36's bench gate enforces the exact
  targets).
* **Wave exit gate:** all packages of the wave merged; `xtask check-dag` (incl. dev-dependencies), `check-unsafe`,
  `lint-guards` green; `xtask catalog-status` shows every hermetic row owned by the wave's packages ported; the next
  wave's owners re-run their `tests/api.rs` against the merged crates.
* **Oracles and vectors.** `cargo xtask oracle install` (WP-00) builds `target/oracle/pc462-py312` (pre-commit 4.6.2 on
  CPython 3.12.3) and `pc462-py313` (on CPython ≥ 3.13.14), hash-locked, each with a `pre-commit-snp-prog` launcher
  (argparse prog patched to `snp`, ADR-058); host interpreters `/usr/bin/python3.12` (3.12.3) and `/usr/bin/python3.13`
  (3.13.14) and `uv` exist on the development machine. Vectors and goldens are generated by xtask tasks and committed;
  CI needs no Python except the differential and gate jobs. Every CI job first checks out cfgv-rs and file-identify as
  siblings at the `deps.lock` SHAs.

### Divergence files (ADR-071)

For every register ID WP-00 creates `docs/divergences/<ID>.md` and `tests/differential/divergences/<ID>.yaml` as
stubs. Afterwards both files belong to the **first** work package of the ID's row in COMPATIBILITY §5 and appear in that
package's owned paths below; the other packages of the row contribute behaviour, not files. WP-35 owns the harness,
scenario corpus, `brand_map.yaml`, the READMEs and the register tooling, never a per-ID file.
